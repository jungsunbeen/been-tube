# City_ 프로젝트 — 채널 설계 문서

> 2026-06-11 기준. 경쟁 채널 4개 오디오 분석(ggg-analy.md, fo-vege-acnh-analy.md)과
> 3개 관점 평가(브랜딩 8/10 / 음악 / 자동화 — 모두 GO)를 거쳐 확정한 내용의 기록.

## 한 줄 컨셉

**"한 영상 = 한 도시의 한 장면"** — 세계 유명 도시의 특정 시간대/날씨에 들리는
lofi jazz 장시간 믹스. 썸네일은 도시 실사 + 중앙에 `도시명_` 타이포.
첫 작품: Florence_ (저녁). 차기작: London_ (비).

시장 포지션: 대형 채널(Lofi Girl, Chillhop)이 전부 일러스트 캐릭터 기반이라
실사+미니멀 타이포는 피드에서 즉각 구분됨. "rainy london jazz" 같은
도시+날씨+장르 롱테일 검색 수요와 정렬. 언더스코어 = "입력 중인 커서 =
계속되는 시리즈"라는 브랜드 장치.

## 분석으로 검증된 공식 (요약)

| 채널 | 전략 | 구조 |
|---|---|---|
| ggg. | 여행형 (키/템포 변화) | 30분 세트(9~10곡) × 2회, 오프너 A장조 83.4 시그니처 |
| fo. | 단일 무드형 | 69분 세트 × 3회, C장조권 ~64 BPM 고정, 세컨더리 도미넌트로 색 |
| 야채상회 | 플레이리스트형 | 63분 세트 × 2회, 키/템포 자유 |
| あつ森 | 커버+앰비언스형 | 90분 세트 × 2회, 빗소리 레이어 전곡 일정 |

공통: **아무도 장시간을 유니크 오디오로 채우지 않는다.** 세트 하나 → 2~3회 통반복.

## 포맷 결정: 3계층 하이브리드

1. **영상 안 = fo.식**: 한 도시는 키 패밀리(본조 + 관계조 2~3곡)와 BPM 고정.
   "장면"은 키/템포가 흔들리지 않아야 유지되고, 단일 무드는 세트 통반복의
   이음새를 가장 잘 숨긴다. 지루함은 코드 컬러(세컨더리 도미넌트, ii-V)로 해소.
2. **시리즈 = ggg.식**: 도시마다 키/BPM을 다르게(60~96 BPM 분산) → 채널 전체가
   키/템포 여행. 영상마다 사운드 정체성이 뚜렷해져 썸네일-사운드 매칭에 유리.
3. **앰비언스 = あつ森식**: 빗소리/카페 소음은 **Suno 프롬프트에 넣지 않고**
   후반작업에서 세트 전체에 한 레이어(-12~-18dB)로 얹는다.
   이유: 곡마다 다른 앰비언스가 생성되면 트랙 경계가 드러나고(이음새를 덮을
   레이어가 이음새를 노출), 키/BPM 실측 정확도도 오염됨(あつ森 분석 실측).

### 표준 스펙
- 한 도시 = 같은 키 패밀리·같은 BPM의 2~4분 트랙 9~10곡 → 30~35분 세트 → ×2회 (≈60~70분)
- 채널이 자리 잡으면 fo.처럼 세트 ×3회(3시간대)로 확장

## 프롬프트 규칙

- **고정 (채널 정체성 80%)**: electric piano, deep round bass, dusty boom bap drums,
  vinyl crackle, heavy lowpass. 음색 템플릿이 곧 브랜드 (ggg.의 시그니처도 곡이
  아니라 "오프닝은 항상 A장조 83.4"라는 템플릿이었음).
- **가변 (도시 색 20%)**: 키/BPM + 컬러 악기 1개 + 무드 한 줄.
- `jazzy seventh chords with gentle 2-5-1 turnarounds` 한 줄로 세컨더리 도미넌트 유도.
- 한 도시 10곡의 단조로움 방지: 트랙별 텍스처 분화 —
  표준 4~5곡 / sparse drums 2곡 / melody-forward 2곡 / no drums 1곡(세트 중반 숨 고르기).
- 무드 줄에 "rain" 같은 SFX 유발 단어는 피한다 (앰비언스는 후반작업이므로).

## Suno 생성 운영 (1일차 실측으로 확인된 사실)

- **BPM은 잘 따른다** (8타이틀 전부 ±3 이내).
- **키는 8개 중 5개만 준수.** 어긋난 건 전부 어려운 키(F#장조→C/Bb, G#단조→C#장조,
  F단조→Bb장조). 무난한 키(A/E/B/D장조)는 전부 준수 → **도시 키는 조표 단순한 키 위주로.**
- 생성 후 반드시 실측 → ±1~2반음은 time_stretch 보정, ±3 이상 재생성.
  단일키 세트에서는 이 QC가 품질의 절반. (time_stretch는 ±2반음까지 사실상 투명,
  ±3부터 드럼 트랜지언트 번짐, ±4 이상 비권장)
- **Suno에서 곡 제목을 목표곡명으로 직접 지정해 생성** → 파일명↔목표 매핑 유지
  (1일차에 자동 제목으로 생성해서 매핑을 추측해야 했던 문제의 재발 방지).
- 곡별 생성 링크/플랜을 기록 (수익화·Content ID 분쟁 대비. 무료 플랜 곡은 상업 이용 불가).

## 썸네일/브랜딩 규칙

- 마스터 16:9 (2560×1440) → 업로드 1280×720 JPG (**2MB 한도**, 품질 85면 ~260KB).
  Florence_ 원본은 3:2 49MB — 센터 16:9 크롭 시 구도가 오히려 개선됨, 그 크롭을 표준으로.
- 폰트/위치 고정: 지오메트릭 산세리프, 가로 중앙, 베이스라인 = 높이 50~55%,
  대문자 높이 = 높이의 12~13%. `도시명_` 표기 통일, 언더스코어는 작은 크기에서
  사라지지 않게 글자보다 약간 두껍게.
- 텍스트가 핵심 랜드마크를 가리지 않게 (Florence_의 원칙 유지).
- 시간대/날씨별 팔레트 패밀리 (저녁=마젠타+골드, 비=틸+네온, 눈=블루+웜라이트).
- **썸네일은 장르를 전달하지 못함(여행 브이로그로 오인 가능) → 제목이 전담**:
  "Florence at Dusk — Lofi Jazz to Study & Relax" 형식.
- 사진 라이선스(상업 이용) 확인 필수. 소스 체계 통일.
- 파일명: `{city}_{weather-time}_thumb_v{n}.jpg`

## 제작 파이프라인

```
[수동] Suno 생성 (제목 지정) + mp3 다운로드 → audio/suno/{도시}/
[자동] ① 키/BPM 실측 → ② 보정(±1~2반음) / 재생성 판정(±3↑)
     → ③ 세트 조립 (마디 정렬 크로스페이드 — 같은 BPM이라 용이)
     → ④ 앰비언스 레이어 (세트 전체, -12~-18dB, ~100Hz 하이패스로 베이스 보호)
     → ⑤ 세트 ×2 통반복 + LUFS -14 정규화 렌더
     → ⑥ 오디오+썸네일 → mp4 인코딩 (ffmpeg 필요 — 미설치)
[수동] 업로드 (당분간 수동 — 미검증 API 프로젝트는 업로드가 강제 비공개됨)
```

- 기존 코드: mix1hour.py(개편 필요 — 변주 순환 → 트랙 나열+통반복, 경로도 구버전),
  check_chords.py(즉시 사용 가능), analyze_chords.py(mp3 미지원 — 수정 필요),
  analyze_mix.py/refine_offset.py(경쟁 채널 분석용), compose_fo.py(자체 작곡 실험).
- 세트 조립 시 트랙 시작 시각 확정 → 설명란용 타임스탬프/챕터 자동 출력 예정.

## 정책/수익화 메모

- Suno **유료 플랜 곡만 상업 이용 가능** (생성 시점 플랜 기준).
- YouTube Data API 자동 업로드는 미검증 프로젝트 강제 비공개 + 테스트 모드 토큰
  7일 만료 문제로 후순위. 쿼터 자체는 충분 (업로드 1건 ≈ 1700/일 10000유닛).
- YPP "반복적/대량생산 콘텐츠" 정책 대비: 아트워크/큐레이션/시리즈 컨셉 등
  부가가치를 채널에 드러낼 것. 설명란 "Made with Suno" 표기 유지.
- 첫 업로드는 unlisted로 1회 올려 정책 플래그 여부 관찰 후 공개.
